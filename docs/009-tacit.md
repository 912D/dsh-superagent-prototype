# 009 · 还差的两块：接入与经验

> 这篇收的是 [007 Architecture](007-architecture.md) 留下的两个缺口。它写的是**为什么这么补**，
> 不是功能清单；要接口细节看模块表里的 `tacit.ts` / `msp-act.ts`。

## 缺口是什么

原型的架构是「Source → Trigger → Eval → Ticket → Worker」，这条链本身没问题。
问题出在链的两端：

| 缺口 | 症状 | 后果 |
| --- | --- | --- |
| **接入** | 每个能力、每台设备都要单独写一个 Source | 接不上的，Agent 永远看不见 |
| **经验** | 同一类情境每次都从头想一遍 | 上次怎么做的，下次用不上 |

两个缺口的共同点：**它们不是「缺功能」，是「缺协议」**。
每接一台设备改一次代码、每遇到一类问题重新想一遍，这不是工程问题，是结构问题。

## 补丁一：一切皆节点，一切皆信号

MSP 本身只解决了一半——它让本机软件**推**给 Agent，Agent 听得见。
但上一版的 Agent 只收不说：它看得见别人发来的信号，却不能主动去驱动任何东西。
于是「接入」仍然是一次性的单向适配。

补上另外三件事，接入才变成协议：

| 工具 | 做什么 | 为什么这样就够了 |
| --- | --- | --- |
| `msp_nodes` | 列出能看见的节点，以及每个节点声明的信号与工具 | 「看得见」是接入的前提；看不见的，等于不存在 |
| `msp_publish` | 往任意路径发一条信号 | 动作也是信号。开灯、暂停下载、广播状态，在 Agent 眼里是同一件事 |
| `msp_call` | 调对端声明过的工具并拿回结果 | 需要返回值的场景（读传感器、要一次计算）走请求/响应 |

关键在于**没有设备特判**：Agent 不需要知道对面是灯、是下载器还是一个传感器，
它只需要知道「发 `device.light.on` 会有人接」或者「`file-watcher` 声明了 `hash` 工具」。

> 判断这条补丁成不成立，看一件事：**接一台新设备，要不要改代码。**
> 要改，就还是适配；不改，才是协议。

## 补丁二：Mem + Exp + SKILL，触发时注入

三件东西回答的是同一个问题——「这次情境，我上次是怎么处理的」：

| 层 | 回答 | 形状 |
| --- | --- | --- |
| **Mem** 记忆 | 这个目录、这台机器、这个人，已知是什么 | 一句可核验的事实 |
| **Exp** 经验 | 遇到这类情况该怎么做 | 「当…就…」+ 理由，可执行、有边界、条件可判定 |
| **SKILL** 技能 | 这类活分几步做 | 一段可复用的操作手册 |

三者**共用一套** frontmatter、一套路径匹配、一个注入点。这是刻意的：
拆成三套实现，就会出现三份解析器、三种命中规则、三处注入点，最后谁也没被真正用上。

### 注入点只有一个

上一版把注入写在 `src/sources/msp.ts` 里——**只有本机信号能用经验**。
这才是 README 里那句「经验 → 行为改变：未验证」的真因：不是经验不够，是别的来源根本拿不到。

这一版把注入移到 `Passes.receive`：那是**所有**来源进 Engine 的唯一入口，
所以 GitHub、飞书、MSP，以及以后新加的来源，都自动拿到同一层注入。

```
Source（github / feishu / msp / …）
  → SourceContext.receive
    → Passes.receive          ← 唯一的注入点：enrichTrigger(trigger)
      → Engine.receive → Eval → Ticket → Worker
```

### 命中才注入

没命中的条目**一个字都不进提示词**。所以库可以越攒越大，提示词不会越来越长——
这是「经验」这种资产能长期积累的前提，否则攒到几十条就把上下文挤爆了。

命中结果同时写进 `trigger.meta.tacit`（各类 id）与 `meta.tacitChars`（块长），
`meta.experience` 保持旧语义不变。这样「这条经验到底生效了没有」在决策记录里查得到，能做消融。

### 库能自己长大

`tacit_create` / `tacit_read` / `tacit_list` / `tacit_disable` 让模型当场把可复用的判断写下来。
四条硬约束写在代码里，不靠提示词自觉：

1. `id` 只允许 `[a-z0-9-]`——它来自模型，`..`、分隔符、盘符不能进 `join`，否则读工具能读走磁盘上任意 `.md`；
2. 不许覆盖同 id（要改就 update）；
3. `disable` 是软删（`enabled: false`），真删要人来——删掉的东西没法复盘；
4. 模型新建最高 L3（先问后做），L1/L2 必须由人上调。

## 格式

三类共用同一份 frontmatter，差别只在「动作键」和「正文」：

```markdown
---
id: downloads-ask
trigger: file.**
condition: file.extension in [exe, msi, dmg]
fact: 这个目录下的安装包一律先问再装        # 记忆写 fact
trust_level: L3
enabled: true
---
# 安装包不可逆
装上去就有副作用，而且卸不干净。
```

- `trigger` 支持 `**`、`file.*`、`file.created`（同族：`file.created` 也适用于 `file.modified`）；
- `condition` 只支持 `true` / `false`、`字段 == 值`、`字段 in [..]`——**看不懂的一律不命中**（凭猜行动比不动更糟）；
- 经验与技能写 `action`（命中后做什么）；技能可以只给 `body`（分步流程）。

目录（都可覆盖，便于测试与多实例）：

| 层 | 默认 | 覆盖 |
| --- | --- | --- |
| Mem | `~/.dsh/tacit/memories` | `TACIT_MEM_DIR` |
| Exp | `~/.dsh/tacit/experiences` | `TACIT_EXPERIENCE_DIR` |
| SKILL | `~/.dsh/tacit/skills` | `TACIT_SKILL_DIR` |
| 根 | `~/.dsh/tacit` | `TACIT_DIR` |

设 `TACIT_DISABLED=1` 整体关闭；经验层是增强，不是前置条件，它坏掉不该让一条信号进不来。

## 怎么验证

这两块的危险在于「看起来通了」：信号收到了、日志里也打印了命中，但行为没变。
所以验证要卡在**可观察的失败**上：

| 要验的 | 失败长什么样 | 怎么看出来 |
| --- | --- | --- |
| 注入是全局的 | 飞书来的工单没有经验注入 | 在飞书来源上发一条命中经验的信号，看 `meta.tacit` 是否非空 |
| 命中才注入 | 没命中的信号，提示词也变长 | 对比 `meta.tacitChars`，未命中应为 0 且 `text` 不变 |
| 库能长大 | 写进去的第二条读不回来 | 调 `tacit_create` 后调 `tacit_list`，再发一条命中它的信号 |
| 接入是协议 | 新设备还要改代码 | 只调 `msp_publish` 驱动一个之前没接过的东西 |

单元层面有两条命令（不需要 `pnpm install`，Node ≥ 24 直接跑 `.ts`）：

```sh
node --test tests/tacit.test.ts
node --test tests/tacit-tools.test.ts
node --test tests/msp-act.test.ts
```

## 诚实的边界

- **经验 → 行为改变**仍然只是「把依据摆到模型面前」，不是「模型一定照做」。真正的闭环要靠
  Eval 的决策阈值，不在这一层。这条补丁把「供给」接上了，**没有**证明「服从」。
- **`msp_call`** 依赖对端实现请求/响应；只会发信号的对端，用它会被拒绝并提示改用 `msp_publish`。
- 三库共用一套匹配规则，好处是不会漂移，代价是**表达力有上限**：`condition` 故意只认三种写法。
  真需要复杂判定的，应该写成技能，让模型自己判断，而不是塞进条件里。
